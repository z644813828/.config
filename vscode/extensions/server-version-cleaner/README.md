# VS Code Server Version Cleaner

При запуске удалённого extension host автоматически удаляет позапрошлую и более старые сборки VS Code Server. По умолчанию сохраняет две самые новые установленные сборки по дате выпуска из `product.json`, а также текущую и любые используемые процессами сборки. Поэтому иногда остаётся больше двух версий. Повторное подключение без перезапуска extension host не вызывает повторную очистку — её можно запустить командой вручную.

Работает на **Linux** через Remote SSH, WSL и Dev Containers. Расширение нужно установить **на удалённой стороне** каждого сервера. Оно использует [workspace extension host](https://code.visualstudio.com/api/advanced-topics/remote-extensions).

## Установка

В каталоге расширения:

```sh
npx @vscode/vsce package --allow-missing-repository
```

Подключитесь к серверу, выполните `Extensions: Install from VSIX…` и выберите полученный `server-version-cleaner-0.1.3.vsix`. Убедитесь, что расширение установлено в разделе удалённого сервера, затем выполните `Developer: Reload Window`.

## Настройки

В пользовательских или удалённых настройках:

```json
{
  "serverVersionCleaner.enabled": true,
  "serverVersionCleaner.keep": 2
}
```

`enabled` управляет автоочисткой. Команда `VS Code Server: Clean Old Versions` запускает очистку вручную и открывает журнал. Журнал также доступен в `Output → Server Version Cleaner`.

## Область очистки

Корень установки определяется прежде всего по `process.execPath` удалённого extension host, включая нестандартные пути. `vscode.env.appRoot` используется только как запасной вариант. Поддерживаются `bin/<commit>` и `cli/servers/Stable-<commit>` / `Insiders-<commit>`. Очищается только текущий канал в текущем корне. Одинаковые commit в двух форматах считаются одной версией. Для legacy-установки канал Insiders определяется по стандартному имени `.vscode-server-insiders`.

Обрабатываются каталоги и ссылки с 40-символьным commit и соответствующим `product.json`. Если дата выпуска отсутствует, используется время изменения каталога или ссылки; это отражается в журнале. Незавершённые установки, расширения, настройки, логи и отдельные CLI-бинарники не удаляются.

В Dev Containers поддерживается путь `bin/linux-<architecture>/<commit>`: расширение удаляет старые каталоги сборок из общего тома `/vscode/vscode-server/bin/linux-<architecture>` и соответствующие симлинки текущего пользователя из `~/.vscode-server/bin` или `~/.vscode-server-insiders/bin`. Сборки без симлинков тоже очищаются. Две последние сборки сохраняются отдельно для текущей архитектуры и канала.

Текущая версия и версии, используемые видимыми процессами пользователя, сохраняются; проверяются как реальные пути, так и пути симлинков. Процессы других контейнеров могут быть невидимы: их старые сборки тоже могут быть удалены. Это может потребовать переподключения и повторной установки сервера в соседнем контейнере.

Для удаления нужны права записи в общий каталог и его содержимое. Если общий кеш принадлежит `root`, расширение при ошибке доступа автоматически пробует `sudo -n` для создания/снятия блокировки и удаления выбранного каталога сборки. Пароль не запрашивается, права владения каталогами не меняются. Если беспарольный sudo недоступен, ошибка выводится в Output; очистка останавливается. Отказ доступа к отдельному `/proc/<pid>/exe` или `cmdline` не останавливает очистку: оба источника читаются независимо, доступные пути используются для защиты работающих версий. Отказы доступа записываются в журнал один раз за очистку. Если оба источника недоступны, определить версию этого процесса нельзя; текущая версия и две последние всё равно сохраняются. Ошибка чтения списка `/proc` или неожиданная ошибка ввода-вывода останавливает очистку. Проверка повторяется перед каждым удалением, но не может полностью исключить гонку с одновременным запуском сервера другим клиентом.

Блокировка `.server-version-cleaner.lock` предотвращает одновременную очистку из нескольких окон. В Dev Containers она находится в общем каталоге `bin/linux-<architecture>` и действует также между контейнерами, использующими этот том. Если extension host аварийно завершился, блокировка может остаться: удалите этот пустой каталог вручную, когда очистка точно не выполняется.

## Проверка

```sh
npm test
```

Тесты используют только временные каталоги, реальные установки сервера не затрагиваются.

## Диагностика

Запустите `VS Code Server: Clean Old Versions`, чтобы открыть Output и повторить очистку. Журнал показывает путь Node.js, `appRoot`, найденный корень, количество установок и причины пропуска. Если ничего не удаляется, скопируйте журнал `Server Version Cleaner`. При ошибке ручной очистки также появляется уведомление.
