# Hex Editor

Локальное расширение VS Code для просмотра и редактирования бинарных файлов.
Интерфейс использует цвета и шрифты текущей темы: слева адреса, в центре значения,
справа ASCII и Data Inspector. Работает с файлами до **32 MiB**.

## Установка и открытие файлов

1. Выполните **Extensions: Install from VSIX…** в палитре команд и выберите собранный `.vsix`.
2. После установки или обновления выполните **Developer: Reload Window**.
3. Откройте файл и выберите **Reopen Editor With… → Hex Editor** («Открыть с помощью»).

Также доступна команда **Hex Editor: Open in Hex Editor**. Отдельного пункта
в контекстном меню проводника нет.

Чтобы все `.bin` файлы открывались в Hex Editor, добавьте в `settings.json`:

```json
"workbench.editorAssociations": {
  "*.bin": "local.hexEditor"
}
```

Если `workbench.editorAssociations` уже есть, добавьте правило в существующий
объект. Уже открытые `.bin` вкладки закройте и откройте заново.

Название и идентификатор пакета — **Hex Editor** / `hex-editor`. Идентификатор
custom editor — `local.hexEditor`.

## Отображение данных

| Элемент | Назначение |
| --- | --- |
| **Hex / Dec в Status Bar VS Code** | Шестнадцатеричное или десятичное представление значений. |
| **uint8_t / uint16_t / uint32_t / uint64_t в Status Bar VS Code** | Объединение по 1, 2, 4 или 8 байтов. |
| **Little Endian** | Порядок байтов для групп и Data Inspector. Снятый флажок означает Big Endian. |
| Линейка колонок | `0–F` для байтов, диапазоны смещений для групп. |
| Адреса слева | Hex-смещения от начала файла; строка содержит 16 байтов при любой группировке. |
| ASCII справа | Печатные ASCII-символы; остальные байты отображаются точкой. |
| Подсветка при наведении | Вся строка и столбец ячейки под указателем, в пределах таблицы. |

Подсветка строки и столбца при наведении имеет фиксированную непрозрачность 6%.

Переключение формата и группировки не меняет файл. `uint64_t` отображается без
потери точности. Неполная группа в конце файла обозначается `—`; для просмотра
отдельных оставшихся байтов выберите меньший тип.

## Навигация, выделение и поиск

- Клик по **Offset** в Status Bar или `Ctrl+G` / `Cmd+G` открывает штатное поле
  ввода VS Code. Кнопка в этом поле переключает Hex/Dec; адрес вводится без `0x`.
- Стрелки, Home/End и Page Up/Down: перемещение по таблице. После выбора группы
  стрелки влево/вправо переходят между группами.
- Клик по группе выделяет её байты. Мышь, Shift+клик и Shift+стрелки расширяют
  выделение; `Ctrl+A` / `Cmd+A` выделяет весь файл.
- При выделении более одного байта Status Bar показывает **N bytes selected**;
  наведите на элемент, чтобы увидеть включительные границы адресов. Размер файла
  расположен справа.
- **Find** в Status Bar или `Ctrl+F` / `Cmd+F` открывает штатное поле поиска VS Code.
  В нём можно переключить Hex/UTF-8, перейти к предыдущему/следующему совпадению и
  очистить запрос. Status Bar показывает количество совпадений.

Если Cmd+F назначен в пользовательском `keybindings.json` на поиск по проекту,
ограничьте это правило условием `activeCustomEditorId != local.hexEditor` или
используйте правила из `vscode/keybindings.json` этого репозитория.

## Редактирование

Редактирование заменяет существующие байты без вставки и изменения размера файла.

В режиме **Hex + uint8_t** две hex-цифры заменяют байт и перемещают курсор дальше.
Escape отменяет незавершённый ввод.

Для ввода целого значения нажмите Enter или дважды щёлкните по числовой ячейке.
Поле принимает число в выбранном формате **Hex / Dec**; **Apply** или Enter
записывает значение с учётом Little/Big Endian. Можно также начать ввод цифрой.
Значения вне диапазона выбранного типа не принимаются. Escape или **Cancel**
закрывает поле без применения.

Изменение группы — одна операция Undo. Доступны обычные команды VS Code:
**Save**, **Save As**, **Undo/Redo**, а также восстановление несохранённых изменений
из резервной копии. ASCII-колонка предназначена для просмотра и выбора байтов;
прямого ввода текстовых символов нет.

## Data Inspector

Панель справа интерпретирует данные начиная с активного байта и обновляется при
клике, перемещении клавиатурой и редактировании.

- `binary`, `octal`;
- `uint8/16/24/32/64` и `int8/16/24/32/64`;
- `ULEB128`, `SLEB128` — значения до 128 бит;
- `float16`, `bfloat16`, `float32`, `float64`;
- `GUID`;
- `ASCII`, `UTF-8`, `UTF-16`, `GB18030`, `BIG5`, `SHIFT-JIS`.

**Little Endian** применяется к многобайтовым числам, UTF-16 и первым трём полям
GUID. LEB128 имеет собственный фиксированный порядок. Текстовые строки показывают
первый декодированный символ; управляющие символы заменяются точкой.
При нехватке байтов отображается **End of File**, при некорректной кодировке —
**Invalid encoding**.

## Ограничения

- Размер файла — до 32 MiB; файл целиком хранится в памяти, отрисовываются только
  видимые строки.
- Поддерживается замена байтов без вставки и удаления. Неполную группу нельзя
  редактировать как целое число; выберите меньший тип.
- Изменения файла внешними программами автоматически не отслеживаются.

## Разработка и сборка

Запуск из корня репозитория в отдельном окне VS Code:

```sh
code --extensionDevelopmentPath="$PWD/vscode/extensions/hex-editor"
```

Сборка локального VSIX требует Node.js и npm. Из папки расширения:

```sh
npx @vscode/vsce package --allow-missing-repository --skip-license --out hex-editor.vsix
```

Проверки логики, числовых форматов и операций с документом:

```sh
npm test
```

Браузерные проверки прокрутки, инспектора, группировки и редактирования находятся
в `test/scroll.browser.cjs`. Для запуска нужны пакет `playwright` и его Chromium:

```sh
node test/scroll.browser.cjs
```

Ориентиры интерфейса: [Microsoft Hex Editor](https://marketplace.visualstudio.com/items?itemName=ms-vscode.hexeditor)
и [KDE Okteta](https://apps.kde.org/okteta/). Это самостоятельная реализация.
