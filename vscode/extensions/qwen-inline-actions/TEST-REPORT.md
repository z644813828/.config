# 0.2.1 — исправление передачи фрагмента

8 ноября 2026, 22:19 МСК.

Проблема: `customQuickActionSendToChat` прикрепляет фрагмент как контекст, но не задаёт границы последующего Apply из чата. Пользователь наблюдал замену всего файла.

Изменение: CodeLens Edit with Continue вызывает `customQuickActionStreamInlineEdit(prompt, range)`. По просмотренным исходникам Continue этот путь передаёт range в `verticalDiffManager.streamEdit` с `isApply: false`. Добавлены явное выделение диапазона и проверка границ целых строк; соседний код на граничных строках вызывает отказ. Нет fallback к chat/apply-file.

Проверки:

- TypeScript compilation и ESLint: успешно.
- Unit: 11/11. Включены функции до/после цели, отказ при соседнем коде на строке, exclusive end в начале следующей строки и CRLF.
- Настоящий VS Code Extension Host: 8/8. Тестовый файл содержит функцию до цели и после неё. Проверяются выбранный диапазон, активный документ и selection, prompt, отсутствие прямого изменения файла, stale snapshot и отсутствие Continue.
- Команда Continue в host-тестах подставная с уникальным ID; проверено, что production ID — `continue.customQuickActionStreamInlineEdit`.

Continue в текущем контейнере отсутствует. Реальная генерация, inline Accept/Reject и Undo после изменений Continue не проверены. Эти тесты не доказывают корректность внутреннего diff конкретной версии Continue. Предыдущие тесты самостоятельного WorkspaceEdit версии 0.1.0 к этому пути не относятся.

VSIX 0.2.1 собирается и устанавливается в текущий контейнер; для Qwen Container требуется установка того же пакета и Reload Window. Networking и конфигурация Continue не меняются. Известные ограничения внутреннего API и порядок ручной проверки описаны в README.
