# Копирование бэкапов VPS с FTP

На OMV ручной запуск восстановлен и успешно выполнен 2026-11-01: скачаны новые
архивы трёх VPS, применено хранение 90 дней (удалено 182 старых архива).
Это подтверждает скачивание, но не полноценное тестовое восстановление.
Расписание после миграции пока не восстановлено.

Рабочий скрипт: `Backups/VPS/pull-vps-backups-from-ftp.py`; DEST_DIR в приватном
env обновлён на `/srv/dev-disk-by-uuid-87c841a9-8d9a-4b8c-96aa-6ea6da074aad/VPS`.
Обновление локального исходника не обновляет установленный файл автоматически.

`pull-vps-backups-from-ftp.py` читает конфигурацию из
`/root/.backup-secrets/pull-vps-backups-from-ftp.env` и рекурсивно скачивает
содержимое `REMOTE_ROOT` в `DEST_DIR`. Совместим с Python 3.5.

После успешного скачивания всех папок удаляет локальные архивы
`vps-config-<server>-<UTC timestamp>.tar.gz` старше `LOCAL_RETENTION_DAYS`
(по умолчанию теперь 30 дней). Сохраняет минимум три последних архива каждого VPS
в каждой папке, даже если они старше этого срока. Возраст определяется
по имени, а не по времени скачивания. Посторонние файлы, `.part`, симлинки
и архивы с некорректной датой не удаляются. FTP-файлы не удаляются.
При ошибке скачивания очистка не запускается.

Добавьте в секретный env-файл на сервере:

```dotenv
LOCAL_RETENTION_DAYS=30
```

Запуск:

```bash
python3 /путь/к/pull-vps-backups-from-ftp.py
```

Сокращение хранения до 30 дней подготовлено локально. На OMV также измените
LOCAL_RETENTION_DAYS в существующем приватном env (или добавьте его): явное
значение 90 перекрывает новый default. Удаление по новому сроку произойдёт только
после следующего успешного скачивания. Уже загруженные старые VPS-архивы в Google
Drive эта локальная политика не удаляет: OMV использует rclone copy, не sync.
